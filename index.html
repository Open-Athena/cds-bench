CDS-bench: Task definitions

Proposal for evaluating procedural reasoning and constrained design on coding sequences. This document specifies task types, easy and hard prompt templates, scoring rules, and proposed compositions.

Draft proposal · Version 0.1 · 25 October 2026

Biological scope

The root biological input is a complete, spliced coding sequence. Its first translated codon and strand are known. The model does not need to discover a gene, identify splice sites, or recognize a protein family from learned sequence patterns.

DNA & coordinatesCoding RNA & pairingProtein & peptides

What an instance can supply

  • A CDS, or a clearly identified panel of CDSs.
  • A requested edit, motif, guide, pairing map, or coding module.
  • Custom score tables, allowed edits, and numerical bounds.

What the benchmark does not ask for

  • Gene discovery, arbitrary genomic splicing, or isoform prediction.
  • Unannotated biological function, folding, expression, or guide efficacy.
  • Noncoding-RNA maturation or whole-transcript processing.

RNA and protein operators have typed input ports for the intermediates they consume. Their prompt previews below wrap those operations in CDS transcription or translation. End-to-end evaluation therefore remains CDS-rooted; the component contracts let us state compositions precisely.

Easy and hard variants

Easy and hard are paired prompt variants of the same instance. Sequence length, edits, constraints, answer, and validator stay fixed. These labels describe reference support—not separate algorithmic difficulty levels.

variant = easy

Reference supplied

Explain the relevant biology and supply lookup facts: all 64 codons, initiator and stop rules, complementarity, IUPAC expansions, cleavage rules, motif definitions, or residue-property tables.

“Use this codon table and these stop rules…”
variant = hard

Reference knowledge assumed

Ask the shortest unambiguous version using standard biological names. Omit reference explanations. Keep custom instance data and every operational convention needed for a unique, comparable score.

“Translate this CDS with NCBI 11…”
A custom pairing-score table, edit budget, allowed mutation set, or host-specific codon weights must remain supplied in both variants. Those are instance data. Hard prompts should never require guessing an unpublished convention.

The expandable task explanations include complete prompt templates, with {{placeholders}} for instance values. The easy translation templates contain an actual 64-codon table. The hard templates retain compact scoring contracts until each convention has a stable benchmark-wide name.

Task schema and scoring

Each task type defines one question, such as translating a CDS or rewriting it without changing the protein. A task instance supplies the actual sequences and requested conditions. For example, a GC-window task needs a window length and an acceptable GC range; those values are given in the question, not inferred from biology. Shared sequence conventions

5′→3′ coding DNA; bases may be separated by spaces. All coordinates are 1-based inclusive unless a field explicitly says otherwise. Ordinary translation uses NCBI code 11. First in-frame stop terminates; no stop character appears in the protein.

Synonymous rewrites keep length, first codon, terminal stop, and translated protein fixed. Alternative codes can be separate future rule sets; v0.1 does not silently substitute one.

Exactness without false biological claims

Guides use a declared sequence-match rule. Digestion uses declared cleavage rules. RNA folding uses a small declared algorithmic model. Protein charge uses supplied pKa values.

These scores establish compliance with the model, not actual cellular efficacy, expression, stability, or retained protein function.

Reverse-complement a CDSdna.reverse_complementGiven a CDS written in one direction, write the complementary DNA strand in its own 5′→3′ direction.

Reverse-complement a CDS

DNA strands pair in opposite directions. The question supplies a CDS as a DNA string and asks for the sequence on the opposite strand. It does not ask where another gene starts or whether the opposite strand encodes a protein.

Replace every base with its DNA partner, then reverse the order so the answer is written 5′→3′. Both steps matter: complementing alone leaves the answer in the wrong direction.

Example

ATG GCT TAA becomes TTA AGC CAT. This operation preserves the number of bases, but it does not preserve the translated protein.

Checking the answer. The answer must match the reverse complement base for base; whitespace between bases is ignored.

Make the coding RNAdna.transcribeGiven coding-strand DNA, produce its coding RNA by replacing T with U while retaining the order of the bases.

Make the coding RNA

The supplied DNA is already the coding strand, written 5′→3′. There are no introns to remove and no strand selection to infer. The question concerns the RNA corresponding to this CDS, not an entire transcript with untranslated regions.

Copy the DNA in the same order and replace every T with U. Keep the start codon and terminal stop codon in the RNA sequence. This creates the RNA input used by editing, pairing, and guide-matching tasks.

Example

Checking the answer. The complete RNA string must be correct and have the same length as the supplied CDS.

Translate DNA to proteincds.translateGiven a CDS and an identified genetic code, return the protein it encodes, ending at the first in-frame stop.

Translate DNA to protein

The CDS is already spliced and oriented correctly. Its first base is the first base of the annotated initiation codon, so the model need not search for an open reading frame. The named genetic code determines how each three-base codon is interpreted.

Read consecutive groups of three bases. Treat the annotated initiator according to NCBI code 11, and end translation at the first stop in that reading frame. Omit the stop and all downstream sequence from the protein answer.

Example

ATG GCT TAA encodes MA. ATG GCT TAA GGT still gives MA: the later GGT is beyond the first stop.

Checking the answer. The final amino-acid string must be exact. A correct prefix followed by extra residues is incorrect.

Role in compositions
  • Protein editing and cloning-site cleanup: verifies that the final DNA encodes the requested protein.
  • Tag assembly, cleavage, and mass calculation: supplies the protein sequence used by the downstream cleavage and mass calculations.

Validate a complete CDScds.validateGiven a candidate complete CDS, identify specific problems with its length, initiation codon, or stop codons.

Validate a complete CDS

This is a check of a supplied sequence, not gene prediction. The candidate may have been damaged by an edit. A complete CDS must be long enough to contain an initiator and stop, have a length divisible by three, start with an allowed initiator, and end with a stop.

Check each condition independently and report all violations. Also look for an earlier stop in the established reading frame. The formal labels below name these findings; they are not biological classes to infer from a sequence family.

Example

ATG TAA GCT TGA has an allowed start and terminal stop, but TAA stops translation early. Report internal_stop.

Checking the answer. The returned set of problem labels must be complete, without adding failures that the sequence does not have.

Map a nucleotide to its codon

Apply a DNA edit scriptvariant.applyGiven a CDS and a list of DNA replacements, insertions, or deletions, return the edited DNA sequence.

Apply a DNA edit script

The question states exactly which edits to make. Every position refers to the original CDS, so an earlier insertion must not shift the coordinates used to interpret a later edit. No biological effect needs to be predicted in this task.

A replacement names an inclusive interval and its new text; empty replacement text deletes that interval. An insertion names the boundary after an original base. Apply the nonoverlapping changes together and retain every unedited base.

Example

If an insertion adds a base near the beginning and a later replacement targets original position 10, it still targets the original tenth base, not the edited string’s tenth base.

Checking the answer. The entire edited DNA string must be correct. Whether it still encodes a valid protein is checked by other tasks.

Classify a substitution effectvariant.protein_effectGiven an internal DNA substitution, determine whether it preserves the protein, changes residues, or introduces an early stop.

Classify a substitution effect

The supplied change replaces DNA without changing its length and does not touch the initiator or terminal stop. Translate the original and edited CDSs using the same code and reading frame.

An unchanged protein is synonymous. A change to one or more amino acids without an earlier stop is missense. A new earlier stop is stop_gained and takes precedence over other residue changes. Insertions, deletions, and start-codon changes are excluded so these three answers cover every instance.

Example

Changing an internal GGT to GGC preserves glycine; changing it to GAT produces aspartate; changing it to TGA creates a stop under code 11.

Checking the answer. The selected category must follow from the actual translated products, rather than from the number of changed DNA bases.

RNA substitutions are specified on the coding RNA after T→U.
teV+
Benchmark TEV cleavage rule: recognize ENLYFQG and cleave ENLYFQ|G. The G remains on the downstream product. Match the complete seven-residue sequence; cut all matches. This is the benchmark exact-match model.
charge+
Independent-site Henderson–Hasselbalch model: a basic site contributes +1/(1+10^(pH−pKa)); an acidic site contributes −1/(1+10^(pKa−pH)). Count one N terminus (basic), one C terminus (acidic), each K/R/H side chain (basic), and each D/E/C/Y side chain (acidic). All other residues contribute zero. Sum every site. No disulfides, modifications, or environment-dependent shifts. The instance supplies pKa values in both variants.

  • INSDC feature-table specification — CDS annotations and nucleotide ambiguity conventions.
  • ExPASy PeptideCutter — protease specificity models and their experimental limits.
  • DNA Chisel examples — translation-preserving sequence constraints and codon optimization.

Evaluation design

Paired prompts, separate score axes

Each underlying instance gets easy and hard prompts with one shared answer and validator. Track reference support separately from sequence length, number of edits, constraint density, or search-space size. Keep tool access and token budgets matched.

Report final-answer correctness. Any intermediate outputs requested by a composition are scored separately; a plausible explanation cannot rescue a wrong sequence.

Prevent sequence leakage

Split related sequence families before deriving tasks. Keep parent CDSs, homologs, recodings, mutants, RNA products, protein products, and composed examples in the same partition.

Hold out selected task combinations as a separate composition-generalization test. Do not train an atomic task on the exact intermediate of a held-out composition.

Designs require validators

Accept every valid candidate unless the task specifies an optimum or tie-break. Verify protein preservation and all constraints on final output. Keep exact-search instances small enough to establish feasibility or optimality.

Accept IMPOSSIBLE only when an independent solver certifies infeasibility. NONE means no matching readout exists, not that an arbitrary search timed out.

Status of this proposal

This document defines candidate task types, prompt templates, and scoring contracts. It does not claim that a dataset, reference implementation, solver, or benchmark score already exists.

Before release: generate instances, implement independent validators, validate easy/hard equivalence, and pilot the task lengths and optimization limits.
