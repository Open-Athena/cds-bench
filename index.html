CDS-bench: Task definitions

Proposal for evaluating procedural reasoning and constrained design on coding sequences. This document specifies task types, easy and hard prompt templates, scoring rules, and proposed compositions.

Draft proposal · Version 0.1 · 25 October 2026

Biological scope

The root biological input is a complete, spliced coding sequence. Its first translated codon and strand are known. The model does not need to discover a gene, identify splice sites, or recognize a protein family from learned sequence patterns.

DNA & coordinatesCoding RNA & pairingProtein & peptides

What an instance can supply

  • A CDS, or a clearly identified panel of CDSs.
  • A requested edit, motif, guide, pairing map, or coding module.
  • Custom score tables, allowed edits, and numerical bounds.

What the benchmark does not ask for

  • Gene discovery, arbitrary genomic splicing, or isoform prediction.
  • Unannotated biological function, folding, expression, or guide efficacy.
  • Noncoding-RNA maturation or whole-transcript processing.

RNA and protein operators have typed input ports for the intermediates they consume. Their prompt previews below wrap those operations in CDS transcription or translation. End-to-end evaluation therefore remains CDS-rooted; the component contracts let us state compositions precisely.

Easy and hard variants

Easy and hard are paired prompt variants of the same instance. Sequence length, edits, constraints, answer, and validator stay fixed. These labels describe reference support—not separate algorithmic difficulty levels.

variant = easy

Reference supplied

Explain the relevant biology and supply lookup facts: all 64 codons, initiator and stop rules, complementarity, IUPAC expansions, cleavage rules, motif definitions, or residue-property tables.

“Use this codon table and these stop rules…”
variant = hard

Reference knowledge assumed

Ask the shortest unambiguous version using standard biological names. Omit reference explanations. Keep custom instance data and every operational convention needed for a unique, comparable score.

“Translate this CDS with NCBI 11…”
A custom pairing-score table, edit budget, allowed mutation set, or host-specific codon weights must remain supplied in both variants. Those are instance data. Hard prompts should never require guessing an unpublished convention.

The expandable prompt sections contain complete templates, with {{placeholders}} for instance values. The easy translation templates contain an actual 64-codon table. The hard templates retain compact scoring contracts until each convention has a stable benchmark-wide name.

Task schema and scoring

A task is a specific operation with named ports, an answer type, and a validator. Broad ideas such as “protein properties” are split into counts, mass, charge, pI, and hydropathy. “RNA redesign” is split by the constraint being solved.

  "task_type": "design.pairing_repair",
  "family": "redesign",
  "domain": "rna",
  "variant": "easy",
  "judge": "constraint",
  "objective": "none"
}
task_type
A literal enum value identifying a task definition and its input, output, and scoring rules.
family / domain
Navigation categories. Domain is one of dna, rna, protein, multi; it identifies the biological layer evaluated.
variant
easy or hard. Changes reference support only.
judge
exact = deterministic answer; set = order-insensitive members; numeric = stated tolerance; constraint = any valid design; optimum = valid design achieving the defined optimum.
objective
None, or one explicitly named optimization objective and tie-break. “Improve expression” is not a permitted unspecified objective.

Shared sequence conventions

5′→3′ coding DNA; bases may be separated by spaces. All coordinates are 1-based inclusive unless a field explicitly says otherwise. Ordinary translation uses NCBI code 11. First in-frame stop terminates; no stop character appears in the protein.

Synonymous rewrites keep length, first codon, terminal stop, and translated protein fixed. Alternative codes can be separate future rule sets; v0.1 does not silently substitute one.

Exactness without false biological claims

Guides use a declared sequence-match rule. Digestion uses declared cleavage rules. RNA folding uses a small declared algorithmic model. Protein charge uses supplied pKa values.

These scores establish compliance with the model, not actual cellular efficacy, expression, stability, or retained protein function.

Evaluation design

Paired prompts, separate score axes

Each underlying instance gets easy and hard prompts with one shared answer and validator. Track reference support separately from sequence length, number of edits, constraint density, or search-space size. Keep tool access and token budgets matched.

Report final-answer correctness. Any intermediate outputs requested by a composition are scored separately; a plausible explanation cannot rescue a wrong sequence.

Prevent sequence leakage

Split related sequence families before deriving tasks. Keep parent CDSs, homologs, recodings, mutants, RNA products, protein products, and composed examples in the same partition.

Hold out selected task combinations as a separate composition-generalization test. Do not train an atomic task on the exact intermediate of a held-out composition.

Designs require validators

Accept every valid candidate unless the task specifies an optimum or tie-break. Verify protein preservation and all constraints on final output. Keep exact-search instances small enough to establish feasibility or optimality.

Accept IMPOSSIBLE only when an independent solver certifies infeasibility. NONE means no matching readout exists, not that an arbitrary search timed out.
